# tools/

The repository root holds only the final build, `GreeblisTown-release.apk` (always the latest build, the author's rule; `check_apk.sh` and the pre-commit hook check that it contains the current asset), the one-file game as bundled in it (`index.html`, the author's request: the whole game lives in one HTML file, and that file is kept at the root as well as inside the Android project; both are copies of the game file `uncompressed.html`, made by `sync_game.py` and checked by `sync_game.py --check` and `check_apk.sh`), and this folder. Everything else lives here: the Android project (`android/`), the game file itself (`uncompressed.html`), the build and release guides (`BUILD.md`, `RELEASE.md`), notes, task and bug lists, game documentation, and the test suite described below.

| File | Purpose |
| --- | --- |
| `RULES.md` | **The author's rules**: every standing rule for this project in one place (the game file, rebuildability, randomness, how the game looks, builds and the repository, names and devices). Read it before any change; add each new rule there in the same change. |
| `uncompressed.html` | **The game file**: the whole game in one HTML file, minified but not compressed (RULES.md 19), with every change made in it directly (since 3.15.43, NOTES 87; the author's original before any of this work is not kept, git history has it). The only source: edit this, then run `build.sh --bump`. |
| `index.compressed.html` | **The compressed version**: the game file minified and compressed into one self-contained page that works as a Bitcoin ordinal (RULES.md 20; about 270 KB). Built from the game file by `build_compressed.js`; never in the APK. |
| `build.sh [--bump] [--no-test]` | **Rebuilds everything that ships from the game file** (RULES.md 2) in one command: 0. minifies the game file (`minify_game.js`, a no-op when it already is), 1. the copies (`sync_game.py`), 2. the pre-painted `tex/` (`prerender_textures.js`), 3. the version (if what ships differs from the root APK, `--bump` raises it by one; without it the build stops), 4. the release APK copied to the root, 5. the compressed version (`build_compressed.js`), 6. the checks (`sync_game.py --check`, `experiment.py --check`, `check_apk.sh`, `test_standalone.js`, `test_compressed.js`; `--no-test` skips the last two). About 7 minutes. |
| `minify_game.js [--check] [file]` | Minifies the game file in place (terser: two safe compress passes, local names shortened, to a fixed point; the license notice, class names and the names the harness and tools read are kept, `RESERVED`). `--check` (quick tier, pre-commit hook) fails if the file is not fully minified. Run by `build.sh`. |
| `minify_identity.js BEFORE [AFTER]` | Proof for a minification (report): boots both with randomness, the clock and the painters' seeds fixed and no `tex/`, records the whole scene at the world-ready point (objects, transforms, geometry and textures bit for bit) and compares (NOTES 89). |
| `build_compressed.js [--check]` | Builds `index.compressed.html` from the game file with the previous compressed version's method (context-mixing model and arithmetic coder; the loader page is `lib/compressed_loader.html`, the encoder is its decoder turned around) and unpacks it again to prove it byte for byte; `--check` (quick tier, pre-commit hook) fails unless it unpacks to the current game file. Run by `build.sh`. |
| `test_compressed.js` | **The compressed version works as a Bitcoin ordinal** (every tier but quick; RULES.md 20): served alone under the content policy ordinals.com uses, it counts LOADING, unpacks, boots, enters VR and draws frames, fetches nothing from elsewhere, no page errors, under 390,000 bytes; a desktop browser gets the "designed for Meta Quest" note. |
| `capture_log.ps1` / `capture_log.sh` | **Live headset log for one session** (Windows PowerShell / macOS-Linux): clears the log, then saves the game's lines and the headset runtime's (`GreeblisServer`, `VrApi`) as UTF-8 until Ctrl+C, so nothing is lost to the ring buffer. Read it with `perf_log.js`. |
| `sync_game.py` | Copies the game file to `index.html` at the repository root and to the APK's asset; `--check` (quick tier, pre-commit hook) fails if either copy differs. Never edit the copies. |
| `experiment.py NAME [src] dst` | Diagnostic and measurement variants (RULES.md 22: never an A/B build of a change; `flashlog`, `nolayers`, `nomultiview`, `nobatch`, `noeffects`, `texcapture`; `--list`): exact text replacements applied to a copy of the game file, never to the game file. `--check` (quick tier, `build.sh`) fails if an experiment's anchors no longer match the minified game file exactly once. Used by `build_experiment.sh`, `prerender_textures.js` and the hitch probe. |

| `test_zfight.js` | Graphical pass: every planar triangle of the built world (the batcher's merged sources in place of its batch meshes; undersides at ground level and overlaps buried inside a third box are listed as hidden) bucketed by its world plane (batched parts resolved through the batcher's `gcPart` attribute); coplanar overlaps between different surfaces are confirmed by rendering the two surfaces alone twice with a 1 mm camera shift and counting flipped pixels. | `git-hooks/pre-commit` | Git hook (`git config core.hooksPath tools/git-hooks`): when the game file, its copies, the compressed version, the root APK or the Gradle file is staged, runs `sync_game.py --check`, `minify_game.js --check` and `build_compressed.js --check` and checks that the root APK contains the current game; refuses the commit if a copy, the compressed version or the root APK is stale or the game file is not fully minified. |
| `test_coincident.js` | Graphical pass, the curved complement of `test_zfight.js`: every triangle of the drawn world (the batcher's merged sources in place of its batch meshes) up to 0.6 m across goes into a 5 cm spatial hash; pairs from different surfaces with different looks and nearly parallel normals are sampled 2 mm apart for points within 0.5 mm of the other's plane and inside it. The growth of that region at a fifth of the tolerance tells a coplanar or tangent contact (a depth fight, fails the pass) from two surfaces crossing at an angle (listed). Contacts the headset cannot show are listed as hidden: undersides at ground level, two closed solids resting back to back (closedness from the edge count), and contacts buried inside a third box. Found the second half of B20. `--save` writes a context view and close-up per pair with the near points in red to `.runs/coinc/`; `--dump NAME` prints the triangles at a named spot. Geometric, because the headless renderer's depth precision is finer than the Quest's and such bands do not flicker here. |
| `zfight_sweep.js` | Optional report: renders a grid of town views and a close orbit of every character three times (0.1 mm and 1 mm camera shifts) and flags views whose flips do not grow with the shift. | `perf_report.js` | **Performance report (full tier, pass/fail).** Boots once into VR and runs the game's situations in sequence (town standing, walking, among the creatures, dialogue, shop panel, battle panel, the Speech, the planting Event in three 30 s phases). Per situation: frame time split into script and GL (draw calls stubbed by default so the software GL's own pipeline compiles do not hide the game's cost; `--draw` rasterises), the top script functions by self time with a source excerpt (the cause), new shader programs / textures / geometries / objects, draw calls, triangles, visible transparent objects, lights, creatures within 25 m, heap. Fails on a shader compile during play, script p99 over 12 ms (16 in the Event), a script frame over 120 ms, or a 30% rise against `perf_baseline.json` (`--update-baseline`). `--only <regex>`, `--no-profile`, `--json out`. Script times are scaled by machine speed: a fixed in-page workload is timed before and after, and the baseline (`perf_baseline.json`, with that time as `calib`) and the absolute limits are scaled by the ratio (NOTES 77). |

| `random_census.js [file] [town s] [Event s]` | Report (not in the tiers): every place the game calls `Math.random`, found by running it (calls through the game's range/pick helpers traced to their caller), counted while loading, in town and in the Event, with the code around each. For the author's randomness decisions (RULES.md 5); seeded texture painters do not appear. Output in `.runs/random_census.json`. |
| `texture_census.js` | **Texture census (standard tier).** Plays pickups, the shop, speaking to every character, a dance battle, a phone call and Nextessa's delivery, text exchanges and the planting Event, and records every canvas the game creates and every GL texture it allocates after loading, with the code that did it; fails on any (a texture made mid-play is what the author's flashes came with, NOTES 82). Also lays out every text exchange's lines as the speech bubble does and fails if one needs a bubble height the loading pool lacks. Since 3.15.48 it also plays the Speech (the Gem and the glue bottle) and the Event to its end (Backpacka's show), and tries up to eight text exchanges. |
| `creature_census.js` | **Creature census (report).** Per character as built in the running game: visible meshes, how many the batcher took and how many draw on their own, triangles, vertices, distinct materials and textures, transparent meshes, parts kept out of the static merge; the measurement companion to CREATURES.md. Writes `.runs/creature_census.json`. |
| `occlusion_census.js` | **Occlusion census (report), exhaustive.** What is drawn but can never be seen, proven before anything is removed: in two world states (town with Zollod's shop and the Portal open; the Event), from a 0.5 m reachable grid flood-filled through the game's own collision (it must reach the church interior), pass A marks the bulk with wide views and GPU occlusion queries (batcher off, every part on its own); pass B aims a narrow view at every object still unseen from every reachable point (1 m apart near it, 2 m beyond) at eye heights 1.0, 1.6 and 2.2 m. Characters, the player's and camera's attachments, the sky and moving objects are not judged. Three browsers in parallel; progress saved for `--resume`. Writes `.runs/occlusion_census.json`. |
| `flash_probe.js` | Report: screenshots consecutive frames around a pickup and reports per-frame brightness jumps (the white-flash investigation, B12; no headless reproduction, kept for the record). |
| `boot_profile.js`, `perf_probe.js` | Reports: CPU profile of the sliced boot (loading time), and scene cost (draw calls, triangles, materials). |
| `build_experiment.sh NAME` | Builds a diagnostic variant APK into `.runs/` (for a measurement only, RULES.md 22; changes go straight into the main build), same package and version as the release. The variants are in `experiment.py` (`--list`), each with a comment saying what it changes; the game file is never changed. |
| `LORE.md`, `lore/` | The Lore Bible, compiled only from the game file (characters, eras, the Ancient, the gallery painting, quests, every gift and gardening line), and a reference image of Gooward's gallery painting (`lore/gallery_painting.jpg`). |
| `VERSIONS.md` | Build history: every version, what changed, what the headset said. |
| `server_harness/` | Desktop-JVM stub for `android.util.Log` plus the `Harness` driver used by `test_server.sh` (includes malformed-request, oversized-line, slow-client and path-traversal cases). |

## Running

```sh
export ANDROID_HOME=/path/to/android-sdk     # platforms/android-34, build-tools/34.0.0
tools/run_tests.sh --smoke                   # spot check, minutes
tools/run_tests.sh                           # standard pass
tools/run_tests.sh --full --resume           # every build (RULES.md 23), hours
tools/run_tests.sh --quick                   # static checks only
```

Individual tools:

```sh
tools/build.sh --bump                        # after editing tools/uncompressed.html: rebuild everything that ships
node tools/minify_game.js --check            # the game file is fully minified
node tools/build_compressed.js --check       # the compressed version unpacks to the game file
python3 tools/sync_game.py                   # copy the game file to index.html and the APK's asset only
python3 tools/sync_game.py --check
tools/test_server.sh                         # or: tools/test_server.sh --serve
node tools/test_entry.js                     # the APK's asset (the game file), all scenarios
node tools/test_play.js                      # 2d and vr scenarios, 20 s each
node tools/test_zfight.js                    # coplanar overlaps / z-fighting in the built world
node tools/test_coincident.js --save         # near-coincident curved surfaces (z-fighting), pictures in .runs/coinc/
node tools/slice_profile.js --top 6          # CPU time per boot slice (loading-time work)
node tools/geom_compare.js a.html b.html     # prove two assets build the same character meshes
node tools/test_play.js <asset> vr-nofloor   # the local-floor fallback scenario
node tools/sharpness_probe.js                # render scale, foveation, texture filtering report
node tools/entry_profile.js                  # what runs across the VR handover
node tools/test_npc_home.js                  # Mushroom return-home scenarios
python3 tools/spellcheck_dialogue.py --who HENNRICK
tools/check_apk.sh tools/android/app/build/outputs/apk/release/app-release.apk
```

Requirements: python3, JDK 17+, Node 18+ with `playwright` (and its Chromium)
installed, Android SDK for the server harness and APK checker.
